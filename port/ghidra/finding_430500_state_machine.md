# Finding: two-level state machine over fixed object slots

Decompiled `FUN_00430500` and its caller `WinMain_` (`0x412b80`) to answer one question:
can this engine be cut into chunks? Then named what the code proved.

Answer: **yes — a two-level state machine driving 0xBE8-byte object slots.**

## Level 1 — `WinMain_` (546 lines of C)

```c
if (g_flag_ae960 == 0) {
    ...
    if (g_gameState == STATE_2)          { FUN_004156a0(); }
    else if (g_gameState - STATE_3 < 3)  { FUN_00430500(iVar4, iVar8); }   /* states 3,4,5 */
    FUN_004046e0();
}
```

`STATE_11`, `STATE_13`, `STATE_14` and `(int)g_gameState < 6` gate other calls, so 0–5 are one
family and 11/13/14 another.

## Level 2 — the phase machine in `FUN_00430500` (1,090 lines)

| phase | what it does |
|---|---|
| `SUB_8` (case 0) | **spawn / level-entry pass** — `ActivateObject(0)` per entry of `g_objCount0`, then `StartSlotEffects()` per entry of `g_objCount1`; ends by setting `g_subState = SUB_9` |
| `SUB_9` (case 1) | **per-frame update** — scans table 0 for `+0x16c == 0`; in table 2, if slot flag `+0x18 & 1` clear and `*slot == 1` → `FUN_00434be0`, and if `+0x5c == 4` → `FUN_0042c200` |
| `SUB_10` (case 2) | message/wait handling; ends by calling `FUN_0042a780`, which tail-jumps into `BuildObjTables` |
| `SUB_12` (case 4) | frame-timing gate — `DAT_004af834/830` vs `DAT_004aea14/a10`, plus ESC (`DAT_004aef88 == 0x1b`) → `FUN_00410600(1)` |

Correction to the earlier reading: `SUB_8` is **not** the update tick. It runs once on level
entry, activates every object, kicks off each slot's animations, then advances itself to
`SUB_9`. `SUB_9` is the per-frame path.

## The object slot: 0xBE8 bytes

`BuildObjTables` (0x428390) proves the layout arithmetically:

```c
ClearObjTables();
g_objCount1 = g_objCount0 = DAT_004de620;        /* count from the loaded level */
puVar3 = &DAT_004bf048;                          /* table 0 + 8 */
do {
    _Dst = puVar3 - 2;
    memset(_Dst, 0, 0xbe8);                      /* slot size = 0xBE8          */
    iVar1 = (&DAT_004de628)[uVar4];              /* source object pointer list */
    *_Dst = iVar1;                               /* slot[0] = object           */
    puVar3[-1] = *(int *)(iVar1 + 0x164);        /* slot[1] = obj->0x164       */
    *puVar3    = *(int *)(*(int*)(iVar1+0x164) + 8);   /* slot[2] */
    (&g_objTable1)[uVar4] = _Dst;                /* table 1 = slot pointers    */
    puVar3[0x2c2] = 0xffffffff;                  /* slot+0xB10 = -1 (no effect)*/
    puVar3[0x2f1] = 1; puVar3[0x2f2] = 1;        /* slot+0xBCC, +0xBD0         */
    uVar4++; puVar3 += 0x2fa;                    /* stride 0x2fa ints = 0xBE8  */
} while (uVar4 < uVar2);
```

Two independent confirmations of 0xBE8: the `memset` length and the `+0x2fa` int stride.

### Slot layout

| offset | contents |
|---|---|
| `0x000` | object pointer |
| `0x004` | `obj->0x164` |
| `0x008` | `*(obj->0x164 + 8)` |
| `0x228` | **5 sub-structs of 0x1C8 bytes each** (`0x228 + 5*0x1C8 = 0xB10`) |
| `0xB10` | active-effect selector, `-1` = none |
| `0xBCC`, `0xBD0` | initialised to 1 |

The 5×0x1C8 block is proven by `StartSlotEffects`, which calls
`StartAnimation(slot + 0x228 / 0x3f0 / 0x5b8 / 0x780 / 0x948, 500, 0, 0)` — differences of
exactly `0x1C8` — and switches on the selector at `slot + 0xB10`.

### Correction: `0x4c13f8` is not a fourth table — it is `&g_objSlots[3]`

`0x4c13f8 - 0x4bf040 = 0x23B8 = 3 * 0xBE8` exactly, and the loop starting there strides
`piVar12 + 0x2fa` ints — the same slot stride. So the earlier `g_objTable0` / `g_objTable3`
split was wrong: there is **one slot array** at 0x4bf040, and the `g_objCount3` loop walks it
from index 3. Hypothesis (unverified): slots 0-2 are the party, 3+ everything else.

Likewise `0x4c90a0` is a **pointer array of slot pointers** — disassembly shows
`mov %ebx,0x4c90a0(,%edi,4)` — now named `g_slotPtrs`. `0x4c9100` begins 24 dwords later and
is a separate array of 0xB34-byte entries (still `g_objTable2`, semantics unknown).

### Slot array size: 13 slots

The slot array must end before `g_slotPtrs`: `0x4c90a0 - 0x4bf040 = 41,056` bytes = 13 slots
(39,624) plus 1,432 spare. That bounds a scene at **13 concurrent object slots** — worth
checking against the level loader (`DAT_004de620`) before relying on it.

### Function names established

| address | name | evidence |
|---|---|---|
| 0x428370 | `ClearObjTables` | zeroes all four counts |
| 0x428390 | `BuildObjTables` | the slot-filling loop above |
| 0x428ec0 | `ActivateObject(pct)` | sets `+0x132 |= 0x10000`, `+0x18` bits, scales `*(short*)(obj+0xa2)` by a 0–100 percentage into `+0x12e` |
| 0x4299c0 | `StartSlotEffects` | the 5×0x1C8 animation starts |
| 0x40e900 | `StartAnimation(ptr, ms, …)` | frame lookup `*(ushort*)(ptr+0x190) * 0x230 + *(*ptr+0x40 + 0x18)`, appends to a list at `+0x194` |

`BuildObjTables` is reached by **tail jumps** from `FUN_0042a780` and `FUN_00406f30`, so it is
a shared level-load tail, not a normal callee.

### Object field map (offsets seen so far)

`+0x18` byte flags (`& 8`, `& 0xffffeffe`), `+0x5c` state (== 4), `+0xa2` short scaled by
percentage, `+0x12e` derived divisor, `+0x132` flags (`| 0x10000`), `+0x164` → animation/resource
root, `+0x16c` counter gating table 0, `+0x190` frame index, `+0x194` animation list head,
`+0x19c` loop flag, `+0x1a4` → bytes at `+0xe`/`+0xf`. Objects and the 0x1C8 effect structs
share this header shape — same "animatable" base.

## Flags — corrected and still open

`g_shutdown` → **`g_flag_ae960`**: 19 references across 6 functions, **all compares, zero
writes**, initial value 0 in the file image. Never set by analysed code: the `do/while` runs
once and the `if (…) break` never fires on it. Neutral name kept. Caveat: undisassembled
`.text` or a computed store could hide a writer, so this is "no writes found".

All four counts/tables live in `.bss`; only `g_gameState` (0x4ae978) and `g_flag_ae960`
(0x4ae960) are initialised data, both 0.

## Negative result: retyping the switch variable does not clear the case labels

`piVar9` (`int *`) → `int`: 1,089 → 1,091 lines, still 8/8 `case (int *)0xN`, variable renamed
throughout. Reverted. There is no named switch variable — Ghidra emits
`switch((int *)(g_subState - SUB_8))` inline, so the cast is its own jump-table inference.
